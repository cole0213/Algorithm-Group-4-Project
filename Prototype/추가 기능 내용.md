## 7. 내부 구조 개선 아이디어

- ~~**BST 인덱스 캐싱** — 현재 검색 요청마다 전체 인덱스 재구성. 포트폴리오 변경 시에만 재빌드하면 성능 개선~~ ✓ `_cache_version` + `invalidate_cache()` + `get_or_build_bst()` 완전 구현
- **Solar API 비동기 큐** — 여러 파일을 동시 업로드 시 LLM 호출을 큐에 쌓아 순차 처리 + 진행 상태 표시 (현재는 요청당 블로킹)
- **session.json 증분 저장** — 현재 추가/삭제 때마다 파일 전체를 재작성. 대용량 시 부담이므로 append 또는 SQLite로 교체 고려
- **LLM 응답 검증 레이어** — 파싱 결과의 hallucination 점수를 원문 대조 자동 계산 (예: 응답 키워드가 원문에 존재하는지 비율 측정)
- ~~**Solar API 속도 제한 처리** — 현재 rate limit 초과 시 그냥 실패. 재시도(backoff) 로직 부재~~ ✓ `_call_solar_api()` 지수 백오프 재시도 (429: 최대 3회, 503: 1회) 구현
- **포트폴리오 청킹 구현** — 현재 8,000자 초과 시 절단 + 경고만. 분할 요청 후 결과 병합하는 방식으로 개선 가능

| ------------------------------------- | --------- | ------------------ |

| 이메일 / 캘린더 연동                  | 있음      | 없음               |
| 역할 기반 접근 제어 (권한 분리)       | 있음      | 없음               |

### 이력서 파서 대비 — Sovren, Rchilli

| 기능                         | 타 서비스 | 우리                        |
| ---------------------------- | --------- | --------------------------- |

| 기능                             | 타 서비스 | 우리                 |

### 우리만의 강점 (타 서비스 대비)

- Solar LLM으로 **비정형 포트폴리오** (블로그, 노션, 텍스트 자유 형식) 처리 가능
- 유사 문장 검출 (Rabin-Karp + LCS) — 표절·중복 지원 감지, ATS에는 없음
- 로컬 전용 운영 — 지원자 개인정보 외부 전송 없음 (개인정보 보호 강점)
- 직군별 파싱 프롬프트 분기 — 프론트엔드·백엔드·데이터 직군 특화 추출
- 완전 오픈 커스텀 가능 — 알고리즘·UI 직접 수정 가능

## 12. 장기 확장 아이디어

- 다중 사용자 지원 + 로그인 (팀 단위 사용, 현재는 로컬 단일 사용자)
- 면접 질문 자동 생성 — 포트폴리오 기반으로 Solar LLM이 질문 초안 제안
- 기술 트렌드 대시보드 — 지원자 전체의 스킬 분포 시각화 (어떤 기술이 많은지)
- 채용 시즌 비교 — 이번 기수 vs 지난 기수 스킬 분포 변화 추이
